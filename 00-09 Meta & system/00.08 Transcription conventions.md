# 00.08 Transcription conventions

Transcription is the largest time investment in this project and the most likely to drift into inconsistency. These rules are fixed and apply to every `## Full text` field in the vault. When a rule is missing, the tie-breakers in [[00.01 Conventions & Design]] §12 apply; changes to this note require user approval.

## 1. Fidelity

- Preserve the source's exact wording, capitalization, punctuation, and grammar, **including its typos**.
- Preserve the source's structural hierarchy: article → section → subsection → paragraph → lettered/numbered clause. Use headings for article, section, and subsection levels; use nested lists for paragraph and clause levels.
- Preserve emphasis: italics as `*italics*`, bold as `**bold**`.
- **Small caps** (used by the agreements for defined terms) are transcribed as plain text; this note is the record of that convention.
- Do not merge short paragraphs. Do not split long ones. If the source is one unbroken paragraph, transcribe one unbroken paragraph.
- Never paraphrase, never summarize into `## Full text`, never "clean up" grammar, never silently fix source typos.

## 2. Page markers

- Insert an HTML comment at every source page boundary: `<!-- p.42 -->`. Page markers use the **printed page number** of the source, not the PDF sheet index; where a page carries no printed number, use the PDF sheet number and say so in `transcription_notes`.
- Markers are invisible in reading view, visible in source mode, and searchable. A reader citing "p. 42" can find the marker; everyone else is not distracted.
- **Web-born / manual-format sources** (ELM, ASM, POM, and any HTML/eCFR material): insert a marker at each section heading instead: `<!-- §432.6 -->`. Do not use page markers for these sources.

## 3. OCR and uncertainty

- Ambiguous OCR: transcribe the best reading and append `<!-- OCR: original reads "xyz" -->` on the same line.
- Garbled OCR: transcribe the best reading and add `<!-- OCR uncertain: verify against _sources/<file> p.N -->`. Do not silently invent a plausible reading.
- Illegible scan: transcribe `[illegible]` and set `transcription_notes: "p.N illegible"`.
- **File-specific regimes** (see [[00.05 Workspace Inventory]] §2):
  - **NPMHU 2022–2025 National Agreement**: text layer present but reading-order-scrambled; extract by coordinate-ordered reconstruction (PyMuPDF) with deduplication, then verify each note against the rendered page. This is not an OCR source, but treat the extraction like OCR for verification purposes.
  - **2025 JCAM**: Paper-Capture PDF (scan + OCR layer). Every transcribed passage is spot-checked against the rendered page before `status: complete`; mark uncertainty with the OCR comments above.
  - **ELM / ASM / POM chapters**: born-digital FrameMaker/Distiller text; verify normally.

## 4. Tables

- Transcribe as markdown tables. Preserve row and column order. Preserve cell content exactly.
- A table too complex for markdown (merged cells, nested headers) is transcribed as a fenced block preserving visual layout; note this in `transcription_notes`.

## 5. Footnotes and endnotes

- Preserve footnote markers inline as `[^1]` at the same position as in the source.
- Reproduce footnote text at the bottom of the note under `## Notes (source)`, even if the footnote text is not otherwise linked.
- Do not silently delete footnotes — they are often where the operative meaning lives.

## 6. Amendments and strikethroughs

- Reproduce strikethrough as `~~struck text~~` when the source shows amended language struck but legible.
- Inserted language shown underlined or in a different weight: transcribe plainly and add `<!-- inserted by amendment YYYY -->` on the same line.
- Superseded versions: both get transcribed. The current version is the section note; the superseded version is a subsection-adjacent note with `status: superseded` and `supersedes:` edges pointing forward.

## 7. Translation of non-prose

- Lettered clause markers (a), (b), (c) → nested list items.
- Roman numeral markers (i), (ii) → nested list items.
- Numbered paragraphs (1), (2) → nested list items.
- Em dashes, en dashes, section marks (§), and pilcrows (¶) → preserve verbatim as Unicode characters.
- Smart quotes → preserve as Unicode characters; do not normalize to straight quotes.

## 8. What "as closely as possible" does not mean

- It does not mean recreating pagination visually. Page markers suffice; no fake page-break whitespace.
- It does not mean preserving fonts or colors. Markdown cannot; the reader does not need it.
- It does not mean transcribing running headers, footers, or page numbers as body text. Those become page markers.
