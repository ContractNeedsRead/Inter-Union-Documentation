## Overview

WebEOR is a web application that provides End-of-Run (EOR) data to United States Postal Service (USPS) employees. Managers, supervisors, and postal technicians use this information to evaluate, maintain, and improve the operation of automated Mail Processing Equipment (MPE). WebEOR can be accessed from any computer with Internet access and a compatible browser.

### Data Collection

The Data Collector imports the run information into the WebEOR database from Postal Service Mail Processing Equipment (MPE). Data collection is automated, but the data collector application allows the user to filter data (for instance, to collect data for a particular facility only) and to import data manually (in case the automatic collection is disabled).

**Note:** The EOR File Import utility replaces the Data Collector feature. See [[#Importing EOR Files]] for more information.

Automated data collection is done for three types of data:

1. **End-of-Run data from Integrated Data Services** - Data from RBCS and AFCS machines is sent to IDS servers, where it is housed until retrieved by the WebEOR Data Collector. The information is retrieved from IDS database files by a Data Collector Service using an Oracle Net connection to the IDS database. The WebEOR Data Collector Service is a software application running on a server at the St. Louis, MO Network Distribution Center (NDC) that accesses the IDS database and automatically retrieves the EOR data from IDS. The service also accesses the WebEOR database and inserts the data. The Data Collector Service runs every 15 minutes.
    
2. **End-of-Day data from RBCS/IPSS machines** - Data from RBCS/IPSS automated equipment is sent to a collection server at the local facility, where the WebEOR Data Collection service retrieves data at 2 a.m. daily.
    
3. **End-of-Day data from machine readers** - Data from automated machines that provide run information through a Remote Computer Reader (RCR) host computer connection, such as the Wide Area Barcode Reader (WABCR), Advanced Facer Canceller System (AFCS), and Delivery Barcode Sorter (DBCS), can be sent to the WebEOR database through a secure connection to the RCR host computer. Machine information is sent to a WebEOR server every 15 minutes.
    

### Report Generator

The Report Generator uses data from the WebEOR database to produce reports for use by local, district, or national managers. There are three types of reports available:

1. **On-Demand Machine Reports** - This customizable report allows the selection of any combination of machines at a specific facility to produce equipment run information for a user-defined date range. See [[#Creating and Running On-Demand Reports]] for more information.
    
2. **Individual Machine Reports** - This is a simple version of the On-Demand Machine Report that allows the viewing and printing of machine run information for a single user-defined machine. See [[#Individual Machine Reports]] for more information.
    
3. **User Defined Reports** - This customizable report allows the selection of any combination of machines, facilities, and/or areas and geographic districts to produce equipment run information for a user-defined date and time range. Users can build reports to be run automatically and sent to a user's Inbox, or they can be run on demand. See [[#User Defined Reports]] for more information.
    

### WebEOR Database Information

The WebEOR database contains run information for automated MPE machines. This information is viewable within the application and can be extracted as reports. The WebEOR database also stores all WebEOR system information, including user and equipment information, schedules, and security settings.

### Machines Supported in the Database

WebEOR currently supports the following machines:

- Advanced Facer Canceller System (AFCS)
- Automated Flat Sorting Machine 100 (AFSM-100)
- Automated Package Processing System (APPS)
- Barcode Sorter (BCS)
- Delivery Barcode Sorter (DBCS)
- Mail Processing Barcode Sorter (MPBCS)
- Multiline Optical Character Reader (MLOCR)
- Next Generation Delivery Barcode Sorter (NGDBS)
- Optical Character Reader (OCR)
- Small Parcel and Bundle Sorter (SPBS)
- Wide Area Barcode Reader (WABCR)

**RBCS Machines:**

- Image Control Unit (ICU) and BCS used as an OSS machine
- Delivery Barcode Sorter (DBCS) used as an OSS machine
- Multiline Optical Character Reader (MLOCR) used as an ISS machine
- Image Processing Subsystem (IPSS)
- Remote Computer Reader (RCR)

**Manual Data Entry:**

- Carrier Piece Count (CPC) information can be manually entered into WebEOR
- Manual Parcel information can be manually entered into WebEOR

### IPSS Production Tracking System

The IPSS Production Tracking System (IPTS) within WebEOR allows End-of-Day (EOD) data from RBCS/IPSS automated machines to be stored. IPTS contains information on the number of mailpieces processed by the RBCS system.

Historically, this data was stored in the Plant Operating Data System (PODS). WebEOR is a replacement for PODS. Data Conversion Operators can view EOD IPSS run information in WebEOR, and managers can use WebEOR to create and view IPTS reports. Additional information is stored in WebEOR from the three main RBCS machines:

**Image Control Unit (ICU):**

- Records captured from the ICU are called transactions
- Transactions that have been encoded with address information during the run
- Transactions that have been sent to the Input SubSystem (ISS)
- Transactions that have entered the RBCS system but not yet been encoded

**Image Processing Subsystem (IPSS):**

- Number of images processed during the run
- Number of images sent to the Remote Computer Reader (RCR)
- Number of images RCR successfully resolved during the run
- Number of images sent to the Remote Encoding Center (REC)
- Number of images for which REC provided encoding results
- Number of images finalized during the run

**Output Subsystem (OSS):**

- Number of mailpieces that received an ID Tag from an ISS machine
- Number of mailpieces the OSS successfully sprayed with a barcode during the run
- Number of mailpieces for which the OSS could not successfully spray a barcode during the run

### Remote Computer Reader

WebEOR collects data from Remote Computer Reader (RCR) servers. This data includes both the total images sent to RCR and the percentage of images that RCR was able to successfully encode. The RCR provides run information both graphically and in comma-delimited form.

### Accessing WebEOR

WebEOR can be accessed by any employee who has received permission to use the system and has valid access credentials (username and password). You can access WebEOR using a web browser from any computer with an Internet connection.

**To open WebEOR:**

1. Open your web browser
2. Type the WebEOR website address into the address bar (the address is available from your local WebEOR administrator)
3. Press Enter

The WebEOR Login screen opens.

**Login Screen:**

The Login screen displays fields for your username and password. If your facility's WebEOR administrator has set up the system to use Single Sign-On (SSO), you will be automatically logged in and will not see this screen.

**To log in to WebEOR:**

1. Type your username into the Username field
2. Type your password into the Password field
3. Click Login

The WebEOR Main Menu opens.

**Note:** If you have forgotten your username or password, contact your local WebEOR administrator for assistance.

- Manage your user preferences

- Log out of WebEOR securely

### User Privileges

WebEOR uses a role-based security system. Each user is assigned one or more roles that determine which features and functions they can access. The following roles are available:

**Administrator:**

- Full access to all WebEOR functions
- Can manage users and assign roles
- Can manage equipment and facilities
- Can view all logs
- Can create and manage all report types

**Manager:**

- Can view all run information
- Can create and run reports
- Can manage run plan comparisons
- Cannot manage users or equipment

**Technician:**

- Can view run information for assigned facilities
- Can add and edit run data
- Can create individual machine reports
- Cannot manage users or equipment

**Read-Only:**

- Can view run information
- Can view reports
- Cannot add, edit, or delete data
- Cannot create new reports

**IPTS User:**

- Can view IPSS production tracking data
- Can create IPTS reports
- Limited access to other WebEOR functions

**Note:** Your WebEOR administrator assigns your role(s) when creating your user account. If you need access to additional functions, contact your local WebEOR administrator.

### Getting Help

WebEOR provides several ways to get help:

**User's Guide:**

- Click the Help link in the right-side menu bar

- View help specific to the current function

**Technical Support:**

- Contact the WebEOR Help Desk for technical problems

### Logging Out of WebEOR

Always log out of WebEOR when you are finished using the application. This ensures that your session is properly closed and protects your account security.

**To log out of WebEOR:**

1. Click the Logout link in the right-side menu bar
2. A confirmation message appears
3. Click OK to confirm logout

You are returned to the Login screen.

**Note:** For security reasons, WebEOR will automatically log you out after 30 minutes of inactivity.

## Accessing Run Information

The EOR Viewer is the primary tool for accessing and managing end-of-run data in WebEOR. The EOR Viewer allows you to:

- View end-of-run summary data for multiple machines
- View detailed run information for individual runs
- Filter data by date, facility, machine type, or other criteria
- Add, edit, or delete run data
- Print run information
- Export data to Excel or other formats

### Importing EOR Files

The EOR File Import utility allows you to manually import end-of-run data files into the WebEOR database. This is useful when automatic data collection is not available or when you need to import historical data.

**To import an EOR file:**

1. From the Main Menu, click "EOR Viewer"
2. Click the "Import EOR File" button
3. Click "Browse" to locate the file on your computer
4. Select the file and click "Open"
5. Verify the file information displayed
6. Click "Import" to begin the import process

The system processes the file and displays the results.

**Import Results:**

- Number of records processed
- Number of records successfully imported
- Number of records with errors
- List of any errors encountered

**Note:** EOR files must be in the correct format to be imported successfully. Contact your WebEOR administrator if you encounter import errors.

### Locating a File

The file browser allows you to navigate your computer's file system to locate EOR files for import.

**To locate a file:**

1. Click the "Browse" button
2. Navigate to the folder containing the EOR file
3. Select the file
4. Click "Open"

The file path is displayed in the file field.

**Supported File Types:**

- .eor files (standard EOR format)
- .txt files (text format)
- .dat files (data format)

### Viewing End-of-Run Data

The EOR Viewer displays end-of-run data in a summary table format. Each row represents a single run, and columns display key run information.

**To view end-of-run data:**

1. From the Main Menu, click "EOR Viewer"
2. The EOR Viewer Summary screen opens
3. Use the filter options to narrow the data displayed
4. Click "Search" to display results

**Summary Data Columns:**

- Run Number - Unique identifier for the run
- Machine ID - Machine that processed the run
- Start Time - When the run began
- End Time - When the run ended
- Duration - Total run time
- Pieces Processed - Total pieces handled
- Throughput - Pieces per hour
- Sort Program - Program used for the run

**Note:** You can customize which columns are displayed using the Column Settings option.

### Filtering EOR Data

The Filter options allow you to narrow the data displayed in the EOR Viewer. You can filter by multiple criteria to find specific runs or groups of runs.

**Available Filters:**

**Date Range:**

- Start Date - Beginning of date range
- End Date - End of date range
- Use the calendar picker to select dates

**Facility:**

- Select from dropdown list
- Choose "All Facilities" to view all data

**Machine Type:**

- Select specific machine type (DBCS, AFCS, etc.)
- Choose "All Types" to view all machines

**Machine ID:**

- Enter specific machine identifier
- Leave blank to view all machines

**Sort Program:**

- Enter sort program number
- Leave blank to view all programs

**Run Status:**

- Complete - Only completed runs
- Incomplete - Only incomplete runs
- All - All runs regardless of status

**To apply filters:**

1. Select your filter criteria
2. Click "Search"
3. The results table updates to show only matching runs

**To clear filters:**

1. Click "Reset Filters"
2. All filter fields return to default values
3. Click "Search" to view unfiltered data

### Using the Calendar to Select Dates

The calendar picker provides an easy way to select dates for filtering run data.

**To use the calendar:**

1. Click the calendar icon next to the date field
2. The calendar picker opens
3. Click the left/right arrows to change months
4. Click a date to select it
5. The selected date appears in the date field

**Calendar Features:**

- Current date is highlighted
- Invalid dates are grayed out
- You can type dates directly in the format MM/DD/YYYY

### EOR Viewer Screens

The EOR Viewer consists of two main screens:

1. **End-of-Run Summary Report** - Displays summary data for multiple runs in table format
2. **Detailed Run Information** - Displays complete data for a single selected run

### End-of-Run Summary Report

The Summary Report displays end-of-run data for multiple machines in a table format. This view allows you to quickly scan multiple runs and identify runs that need attention.

**Summary Report Features:**

- Sortable columns (click column header to sort)
- Customizable column display
- Export to Excel or CSV
- Print preview and print functions
- Color-coded status indicators

**Status Indicators:**

- Green - Normal run, no issues
- Yellow - Warning, minor issues detected
- Red - Error, significant problems detected

### Sorting Run Information

You can sort the run information in the Summary Report by clicking on column headers. This helps you organize the data to find specific information quickly.

**To sort run information:**

1. Click on any column header
2. The data sorts in ascending order
3. Click the header again to sort in descending order
4. An arrow icon indicates the current sort column and direction

**Sortable Columns:**

- Run Number
- Machine ID
- Start Time
- End Time
- Duration
- Pieces Processed
- Throughput
- Sort Program
- Status

**Multi-Column Sorting:**

1. Hold Shift while clicking column headers
2. Sort by multiple columns in sequence
3. The sort order is indicated by numbers in the header

### Detailed Run Information

The Detailed Run Information screen displays complete data for a single selected run. This screen provides in-depth information about run performance, errors, and processing statistics.

**To view detailed run information:**

1. From the Summary Report, click on a run number
2. The Detailed Run Information screen opens
3. Review the detailed data
4. Click "Back to Summary" to return to the Summary Report

**Detailed Information Sections:**

**Run Header:**

- Run Number
- Machine ID
- Facility
- Start Date/Time
- End Date/Time
- Duration
- Operator ID

**Run Statistics:**

- Total Pieces Processed
- Pieces Per Hour (Throughput)
- Sort Program
- Mail Class
- Operation Number

**Performance Metrics:**

- Actual Run Time
- Idle Time
- Fault Time
- Utilization Percentage

**Bin Information:**

- Bin Number
- Bin Description
- Pieces to Bin
- Percentage of Total

**Error Information:**

- Error Code
- Error Description
- Error Count
- Error Timestamp

**Additional Data:**

- Operator Notes
- Maintenance Notes
- Run Comments

### Adding a Run

In some cases, you may need to manually add a run to the WebEOR database. This might be necessary if automatic data collection failed or if you need to enter historical data.

**To add a run:**

1. From the EOR Viewer Summary screen, click "Add Run"
2. The Add Run screen opens
3. Complete all required fields (marked with *)
4. Enter optional data as needed
5. Click "Save" to add the run to the database

**Required Fields:**

- Machine ID
- Start Date/Time
- End Date/Time
- Sort Program
- Pieces Processed

**Optional Fields:**

- Operator ID
- Mail Class
- Operation Number
- Run Comments
- Bin data

**Note:** Manually added runs are flagged in the database and can be identified in reports.

### Editing End-of-Run Detailed Data

You can edit run data to correct errors or add missing information. Only users with appropriate privileges can edit run data.

**To edit run data:**

1. From the Summary Report, click on the run number
2. The Detailed Run Information screen opens
3. Click "Edit Run"
4. The Edit Run screen opens with current data populated
5. Modify the data as needed
6. Click "Save" to save your changes
7. Click "Cancel" to discard changes

**Editable Fields:**

- Operator ID
- Mail Class
- Operation Number
- Run Comments
- Bin data (add, edit, or delete bin records)

**Note:** Some fields cannot be edited after a run is created (Machine ID, Start/End times). If you need to change these fields, delete the run and add a new one.

**Edit History:**

- All edits are logged in the Manual Data Entry Log
- The log records who made changes and when
- Original values are preserved for audit purposes

### Printing End-of-Run Detailed Data

You can print detailed run information for your records or to share with others.

**To print run data:**

1. From the Detailed Run Information screen, click "Print"
2. The Print Preview opens in a new window
3. Review the print layout
4. Click "Print" in the browser's print dialog
5. Select your printer and options
6. Click OK to print

**Print Options:**

- Portrait or Landscape orientation
- Include/exclude bin details
- Include/exclude error information
- Include/exclude charts and graphs

**Print Preview Features:**

- Page through multiple pages
- Zoom in/out
- Adjust margins
- Select specific pages to print

**Note:** You can also export run data to PDF using the Export function before printing.

### Deleting a Run

You can delete runs from the database if they were entered in error or are no longer needed. Only users with appropriate privileges can delete runs.

**To delete a run:**

1. From the Summary Report, select the checkbox next to the run(s) to delete
2. Click "Delete Selected"
3. A confirmation dialog appears
4. Click "OK" to confirm deletion
5. The run is removed from the database

**Warning:** Deleted runs cannot be recovered. Make sure you want to permanently delete the run before confirming.

**Deletion Rules:**

- You cannot delete runs that have been uploaded to other systems
- You cannot delete runs older than 90 days (configurable by administrator)
- All deletions are logged in the Activity Log

### Refreshing Machine Runs

The Refresh function updates the displayed data with the most recent information from the database. This is useful when multiple users are working in the system simultaneously.

**To refresh the data:**

1. From the EOR Viewer Summary screen, click "Refresh"
2. The system queries the database
3. The display updates with current data

**Auto-Refresh:**

- You can enable auto-refresh in your user settings
- Auto-refresh updates the display every 5 minutes
- Auto-refresh is disabled by default to conserve bandwidth

## Appendix A: Glossary of Terms

**Address Management System (AMS)** - The system that creates and maintains address information used in sort programs.

**Advanced Facer Canceller System (AFCS)** - A machine that processes letter mail by facing, canceling, and sorting. The AFCS can be equipped with an ISS to capture images for RBCS processing.

**Automated Flat Sorting Machine (AFSM)** - A machine that processes flat mail using optical character recognition and barcode reading technology.

**Automated Package Processing System (APPS)** - A machine designed to sort packages using barcode technology.

**Barcode Sorter (BCS)** - A machine that reads barcodes on mailpieces and sorts them to designated bins according to the sort program.

**Carrier Piece Count (CPC)** - Manual count of mail pieces processed through carrier case operations.

**Data Collection Server (DCS)** - A server that collects data from mail processing equipment and holds it until transferred to a database.

**Database Transfer** - The process of moving data from one database to another, such as uploading WebEOR data to IDS.

**Delivery Barcode Sorter (DBCS)** - A high-speed sorting machine that reads barcodes and sorts letter mail to carrier route and delivery sequence.

**Delivery Point Sequence (DPS)** - Mail sorted to the order in which it is delivered by the carrier.

**Decision Storage Unit (DSU)** - A component of the RBCS that stores ZIP Code results for mailpieces processed through the system.

**End-of-Day (EOD)** - Data collected at the end of a processing day, typically summarizing all activity for that day.

**End-of-Run (EOR)** - Data collected when a machine completes a processing run.

**First Handling Pieces (FHP)** - Mail pieces counted on their first pass through a distribution operation.

**ID Tag** - A unique identifier applied to a mailpiece by an ISS. The ID Tag allows the mailpiece to be tracked through the RBCS. The tag includes information about which Input Subsystem applied it, the day and time, and a sequence number.

**Image Processing Subsystem (IPSS)** - The central computer in each facility used to collect and store images for RBCS processing. It manages both the processing of images captured by an ISS and the results of processed images.

**Image Processing Unit (IPU)** - A component of the RBCS that controls the flow of images from the Image Control Unit to keyers' terminals, then receives results to send to the DSU.

**Image Record Descriptor (IRD)** - A file assigned by the ISS to an image being sent to the RCR. The IRD is updated with each step the image takes through the RBCS.

**Input Subsystem (ISS)** - A modification to an OCR, DBCS, or AFCS machine to capture images of mailpieces. The ISS applies an ID Tag to each letter and sends resolved images to the RBCS for further processing.

**Integrated Data System (IDS)** - The system that collects data from all mail processing machines. Data is automatically sent to IDS via data collection servers (DCS). The system is controlled remotely from USPS sites at Merrifield, VA, and Norman, OK.

**IPSS Production Tracking System (IPTS)** - A set of functions within WebEOR that allow EOD data from RBCS/IPSS automated machines to be stored.

**Mail Processing Barcode Sorter (MPBCS)** - Most are retrofitted with an OSS modification to process mailpiece results returned from the Remote Barcoding System. The MPBCS is two-sided and has 96 bins with one mechanical reject bin on each side.

**Mail Processing Equipment (MPE)** - Machinery used to perform distribution of mail and other functions such as canceling and culling. This includes automated and mechanized machinery as well as distribution cases.

**Management Operating Data System (MODS)** - An accounting system used to provide local USPS management with information on the relationship between workloads and actual versus planned hours.

**Mechanical Reject** - Mail that cannot be tracked properly because of mechanical problems on the machine and cannot be placed in its proper bin; also the name of the bin in a sort program where this type of mail is sent.

**Multiline Optical Character Reader (MLOCR)** - A 44 or 60 stacker machine that applies ID Tags, captures an image of the mailpiece, resolves (encodes) the delivery address, and sprays the corresponding POSTNET barcode. Unresolved mail is sent to the RBCS for further processing.

**National Directory Support System (NDSS)** - The system that maintains and updates the databases and files necessary to sort mail on automated equipment. The Sort Program System (SPS) and address directories reside on the NDSS.

**Network Distribution Center (NDC)** - Facilities that distribute parcel post, media mail, standard mail, and periodicals in bulk form.

**None** - Indicates the volume is not finalized to the route or box on this operation (i.e., primary options such as 871, 872, 873, 874, 875).

**Optical Character Reader (OCR)** - A machine that locates the address information on the face of the mailpiece, reads the street address, city, state, and ZIP Code, and attempts to locate a match in the address database. If a match is found, a barcode is printed on the letter, and the mailpiece is sorted to a bin according to the sort program.

**Output Subsystem (OSS)** - A modification to a BCS or DBCS that detects mailpieces with an ID Tag, retrieves ZIP Code results from the decision storage unit (DSU), matches the results with the actual mailpiece (based on the ID Tag), then prints and verifies a POSTNET barcode on the front of the mailpiece.

**Postal Numeric Encoding Technique (POSTNET)** - The barcode system used to represent ZIP Codes on mailpieces.

**A Field** - A POSTNET barcode that represents a 5-digit ZIP Code destination and the correction character, allowing mail to be sorted to the carrier; the field is enclosed by framing bars.

**B Field** - A POSTNET barcode representing the zone, the add-on (+4), and the correction character, with framing bars enclosing the field. It is used in conjunction with an A field. The B field allows mail to be sorted to the carrier via sector/segment.

**B+ Field** - A POSTNET barcode representing the zone, the add-on (+4), the last two digits of the street number, and the correction character with framing bars enclosing the field. It is used in conjunction with an A Field. The B+ field allows mail to be sorted in delivery point sequence to the carrier.

**C Field** - A POSTNET barcode representing the SCF, the zone, the add-on (+4), and the correction character with framing bars enclosing the field. It allows mail to be sorted to either the carrier route or sector/segment.

**C+ Field** - A POSTNET barcode representing the zone, the add-on (+4), the last two digits of the house number, and the correction character with framing bars enclosing the field. It allows mail to be sorted in delivery point sequence.

**Processing and Distribution Center (P&DC)** - A central mail facility that processes and dispatches part or all of both incoming and outgoing mail for a designated service area. The facility is usually a sectional center facility (SCF) or general mail facility (GMF), but it can also be a dedicated mail processing center with no "public" post office attached.

**Remote Barcoding System (RBCS)** - A collection of subsystems designed to allow letter mail that is not optically readable to be barcoded and processed in the automated mail stream.

**Remote Computer Reader (RCR)** - A component of the Remote Barcoding System (RBCS) that attempts to resolve images electronically. Images not resolved by RCR are sent to a remote encoding center for manual coding.

**Remote Encoding Center (REC)** - The facility where data conversion operators input data from mailpiece images sent by RBCS. Keying results are returned to the plant for further processing on the OSS.

**ROUTE** - Indicates the zones are committed to Route level regardless of the operation number.

**Run Plan Generator (RPG)** - A USPS software application used to model and compare run plans.

**Scheme** - A list of address items, by ZIP Code, for the distribution of mail by its destination or delivery as determined by mail processing operations.

**Sector** - The sixth and seventh digits of a ZIP+4.

**Segment** - The eighth and ninth digits of a ZIP+4.

**Sector/Segment** - The sixth, seventh, eighth, and ninth digits of a ZIP+4; also called the Plus4; a type of two-pass sort program.

**Sector Segment (SSG)** - Indicates the zones on the Sort Program are committed to SSG and are mapped to a SSG operation number (i.e., 879).

**Sector Segment (SSG) NOT RUN** - Indicates the zones on the Sort program are planned for SSG but are not yet mapped to an SSG operation number (i.e., 876).

**Small Parcel and Bundle Sorter (SPBS)** - A machine that will sort bundled letters, bundled flats, or small parcels to 100 sort destinations.

**Soft Stop** - A soft stop occurrence will only be reported for the end of run report when it is pressed by an operator during a run.

**Sort Program** - A computerized scheme for assigning ZIP Codes or keycodes to bins.

**Sort Program System (SPS)** - The application that supports the creation, maintenance, and updating of sort programs for postal automated mail processing equipment (MPE) using data from the Address Management System.

**Split Run** - A run that ends in a different MODS day (or tour) than the day or tour it started. WebEOR automatically assigns the run to the MODS day or tour where the majority of the run falls.

**Stand-Alone Mail Prep (SAMP)** - A Prep station is considered to be processing mail when it is on, started, and not faulted.

**Subsequent Handling Pieces (SHP)** - First handling pieces that require more distribution into subsequent or downstream manual operations are projected as SHP, based on local mail flow densities or weights.

**System Control Console (SCC)** - A microcomputer used to monitor and control the IPSS.

**Total Pieces Handled (TPH)** - TPH is the sum of FHP and SHP for non-automated environments. For automation or mechanization operations, the actual TPH is from meter readings from the equipment.

**UNIT** - Indicates the zone(s) are only committed to 5-digit sorting.

**Video Display Terminal (VDT)** - A monitor used to display images for coding by DCOs.

**Web End-of-Run (WebEOR)** - The centralized database that stores and allows reporting on end of run data. The data is intended for use by USPS technical and operations managers.

## Working with IPTS

The IPSS Production Tracking System (IPTS) within WebEOR allows users to view, edit, and report on projected and actual workload data from RBCS/IPSS automated machines.

### Viewing and Editing Projected Workload Data

Projected workload data represents estimates of mail volume and processing requirements for RBCS operations. This data helps managers plan console staffing and resource allocation.

### Viewing Projected Workload Data

**To view projected workload data:**

1. From the Main Menu, click "IPTS"
2. Click "Proj Wkld Data"
3. Enter a date and time to view
4. Click "View"

**Projected Workload Data Displayed:**

- Productivity (pieces per console per hour)
- System Leakage percentage
- ISS Pieces (Input Subsystem)
- IPU Pieces (Image Processing Unit)
- Mode A, B, C, D piece counts
- 11-Digit, 9-Digit, 5-Digit piece counts
- Console requirements
- Scheduled hours

### Editing Projected Workload Data

Users with appropriate privileges can edit projected workload data to adjust estimates based on current conditions.

**To edit projected workload data:**

1. From the Projected Workload View screen, click "Edit"
2. The Edit Date Select screen opens
3. Select a date/time template to use as a starting point
4. Click "Continue to Edit"
5. Modify values in the "Modified" columns
6. Click "Save" to retain changes or "Cancel" to discard

**Edit Options:**

- Load Template Data - Select data from another date/time
- Clear Screen Data - Clear all modified values
- Save - Save all changes
- Cancel - Return without saving

### Generating and Viewing Standard IPTS Reports

WebEOR provides seven standard IPTS reports:

**1. Actual to Projected Workload Report**

- Compares projected console and mailpiece estimates to actual results
- Shows variance between planned and actual performance

**2. Daily Performance Report**

- Shows workload statistics in half-hour increments
- Displays image types keyed
- Includes production statistics

**3. End-of-Day Upload Report**

- Total mailpieces processed at IPU, ISS, OSS, and RCR levels
- Unresolved vs. resolved mailpiece counts
- Breakdown by ZIP Code type (5-digit, 9-digit, 11-digit)

**4. ILU Report**

- Summary counts and percentages for each Input Subsystem
- Performance metrics by ISS

**5. RBCS Consolidated Report**

- Compares projected and actual RBCS statistics
- System-wide performance overview

**6. Snapshot Report**

- VDT and DSU process statistics in half-hour increments
- Real-time system status

**7. Daily Workload Report**

- Console usage
- Mailpiece processing counts
- Overtime hours resulting from workload

**To generate an IPTS report:**

1. From the Main Menu, click "IPTS"
2. Click "Generate Rpts"
3. Select either Standard Report or Custom Report
4. Select a site (Total, RIOSS 1-5, or Local)

6. Enter End Date/Time (or click "+1 Day" for 24-hour report)
7. Click "Generate"

The report generates and opens in a new window.

## Data Retention

WebEOR maintains data retention policies to manage database size and ensure compliance with USPS data retention requirements.

### Data Retention Policy

The Data Retention Policy defines how long different types of data are retained in the WebEOR database before being purged.

**Default Retention Periods:**

**Run Data:**

- EOR data - 730 days (2 years)
- IPTS data - 730 days (2 years)
- CPC data - 730 days (2 years)
- Manual Parcel data - 730 days (2 years)

**Logs:**

- Activity logs - 365 days (1 year)
- Exception logs - 365 days (1 year)
- System logs - 365 days (1 year)

**Reports:**

- Generated reports - 90 days
- Custom report definitions - Retained indefinitely

**Configuration Data:**

- Equipment data - Retained indefinitely
- User data - Retained indefinitely
- Mapping data - Retained indefinitely

### Modifying Data Retention Policy

Administrators can modify retention periods based on organizational needs.

**To modify the data retention policy:**

1. From the Main Menu, click "Admin"
2. Click "Data Retention"
3. Click "Policy"
4. Select the data type to modify
5. Enter the new retention period (in days)
6. Click "Save"

**Note:** Changes to retention policy only affect future data purges. Existing data beyond the new retention period is not automatically deleted until the next scheduled purge.

### Data Retention Schedule

The Data Retention Schedule controls when purge operations run to remove old data.

**Default Schedule:**

- Runs daily at 2:00 AM local server time
- Purges data older than retention policy limits
- Logs all purge operations

**Purge Process:**

1. Identifies data past retention period
2. Archives data to backup location (if configured)
3. Deletes data from active database
4. Logs purge statistics
5. Updates database statistics

### Adding Data Retention Schedule

Administrators can create custom retention schedules for specific data types or facilities.

**To add a retention schedule:**

1. From the Data Retention screen, click "Schedule"
2. Click "Add Schedule"
3. Enter schedule details:
    - Schedule Name
    - Data Type
    - Retention Period (days)
    - Purge Frequency (Daily/Weekly/Monthly)
    - Purge Time
    - Facilities (if applicable)
4. Click "Save"

### Modifying the Data Retention Schedule

**To modify an existing schedule:**

1. From the Data Retention Schedule screen, select a schedule
2. Click "Edit"
3. Modify the schedule parameters
4. Click "Save"

**Note:** Schedule changes take effect at the next scheduled run time.

## Appendix B: Automation Proficiencies Indicator (API) Formulas

This appendix provides the formulas used to calculate Automation Proficiency Indicators in WebEOR.

### Integration of Quality Index into the OEE Formula

Overall Equipment Effectiveness (OEE) is calculated by integrating the Quality Index with availability and performance metrics.

**OEE Formula:**

```
OEE = Availability × Performance × Quality
```

Where:

- **Availability** = (Operating Time) / (Planned Production Time)
- **Performance** = (Actual Output) / (Theoretical Maximum Output)
- **Quality** = (Good Pieces) / (Total Pieces)

### The Plant-Level Letter Mail Quality Index Formula

**Plant-Level Quality Index Formula:**

```
Plant Quality Index = Σ(Machine Quality Index × Machine Pieces) / Σ(Machine Pieces)
```

This provides a weighted average quality index across all machines at the plant.

### Machine-Level Quality Indexes Formulas

#### The AFCS/ISS Machine-Level Quality Index Formula

**AFCS/ISS Quality Index:**

```
AFCS/ISS Quality Index = (Pieces with Good Images) / (Total Pieces Fed)
```

Where:

- **Pieces with Good Images** = Pieces successfully imaged and resolved or sent to RBCS
- **Total Pieces Fed** = All pieces entered into the AFCS

#### The MLOCR/ISS Machine-Level Quality Index Formula

**MLOCR/ISS Quality Index:**

```
MLOCR/ISS Quality Index = (Pieces Resolved + Pieces Sent to RBCS) / (Total Pieces Fed)
```

Where:

- **Pieces Resolved** = Pieces successfully encoded on the MLOCR
- **Pieces Sent to RBCS** = Pieces with images sent for remote processing
- **Total Pieces Fed** = All pieces entered into the MLOCR

#### The DBCS Machine-Level Quality Index Formula

**DBCS Quality Index:**

```
DBCS Quality Index = (DPS Pieces + Carrier Route Pieces) / (Total Pieces Sorted)
```

Where:

- **DPS Pieces** = Pieces sorted to Delivery Point Sequence
- **Carrier Route Pieces** = Pieces sorted to carrier route
- **Total Pieces Sorted** = All pieces successfully sorted

#### The MPBCS/OSS Machine-Level Quality Index Formula

**MPBCS/OSS Quality Index:**

```
MPBCS/OSS Quality Index = (Pieces with Successful Barcode Spray) / (Total Pieces with ID Tag)
```

Where:

- **Pieces with Successful Barcode Spray** = Pieces successfully sprayed with barcode
- **Total Pieces with ID Tag** = All pieces received from RBCS with ID Tags

## Appendix F: Frequently Asked Questions

This appendix provides answers to frequently asked questions about WebEOR.

**Q: How do I reset my password?** A: Contact your local WebEOR administrator to reset your password.

**Q: Why can't I see certain machines in WebEOR?** A: Your user account may not have access to those machines. Contact your WebEOR administrator to request access.

**Q: How far back does WebEOR retain data?** A: By default, WebEOR retains run data for 730 days (2 years) and log data for 365 days (1 year). Your facility may have different retention settings.

**Q: Can I export data from WebEOR?** A: Yes, most screens in WebEOR have a CSV export option. Click the "CSV" link to download data in comma-separated values format.

**Q: How do I create a custom report?** A: Use the User Defined Reports feature. Navigate to Reports > User Defined Reports and click "Create New Report."

**Q: What browsers does WebEOR support?** A: WebEOR supports Internet Explorer 9.0+, Mozilla Firefox 29.0+, and Google Chrome 35.0+.

**Q: Why is my data not showing up in WebEOR?** A: Data collection may be delayed. Check the IDS Connection status and contact your WebEOR administrator if data is missing for more than 24 hours.

**Q: Can I schedule reports to run automatically?** A: Yes, use the User Defined Reports feature to create scheduled reports that run automatically and deliver to your inbox or email.

**Q: How do I add a new machine to WebEOR?** A: Contact your WebEOR administrator or use the Machine Catalog function if you have appropriate privileges.

**Q: What is the difference between MODS Date and Run Date?** A: MODS Date is the accounting date assigned by the Management Operating Data System. Run Date is the actual calendar date when the run occurred. These may differ for runs that cross midnight.

## Appendix L: Login for PCs That Are Not ACE Workstations

This appendix provides instructions for accessing WebEOR from PCs that are not ACE (Access to Corporate Environment) workstations.

### Non-ACE Login Requirements

**Requirements:**

- Internet connection
- Supported web browser (IE 9.0+, Firefox 29.0+, Chrome 35.0+)
- Valid WebEOR username and password
- VPN connection (if accessing from outside USPS network)

### Accessing WebEOR from Non-ACE PC

**Step 1: Establish VPN Connection (if required)**

1. Launch your VPN client
2. Enter your VPN credentials
3. Connect to the USPS network

**Step 2: Open Web Browser**

1. Launch your web browser
2. Navigate to the WebEOR URL (provided by your WebEOR administrator)

**Step 3: Login to WebEOR**

1. Enter your WebEOR username
2. Enter your WebEOR password
3. Click "Login"

### Troubleshooting Non-ACE Access

**Problem: Cannot connect to WebEOR**

- Solution: Verify VPN connection is active
- Solution: Verify WebEOR URL is correct
- Solution: Contact your network administrator

**Problem: Login fails**

- Solution: Verify username and password are correct
- Solution: Contact your WebEOR administrator to verify account status

**Problem: Slow performance**

- Solution: Check internet connection speed
- Solution: Close unnecessary browser tabs
- Solution: Clear browser cache and cookies

### Security Considerations for Non-ACE Access

- Always log out when finished using WebEOR
- Do not save password in browser
- Use secure internet connections only
- Do not access WebEOR from public computers
- Keep VPN software up to date
